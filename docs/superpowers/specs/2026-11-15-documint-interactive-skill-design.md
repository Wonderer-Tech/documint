# DocuMint Interactive Skill — Architecture

## Intent
Reuse the **actual VS Code Local Mode** SourceAnalyzer, LocalDocumentationModel,
LocalCodeMapData and HTML renderer to generate the same fully interactive
`documint/documentation.html` from a Skill in an execution-capable host.
No MCP, external service, cloud model, GitHub Action, or VS Code runtime.

## Approach
The skill invokes a single Node.js executable generated by esbuild from the
repository's existing TypeScript implementation. The executable discovers files
on disk, calls `SourceAnalyzer.analyzeProject`, then
`buildLocalDocumentationDocument` plus the same offline HTML hardener used by
VS Code. Its output files and cache manifest match Local Mode. The package
builder includes this compiled executable in the skill ZIP so installation
is not dependent on an NPM install in the consumer's workspace.

## Guarantees
- The visual HTML and Markdown rendering implementation **is shared**, not
  reimplemented. Interactive project map, reader UI, search, tree, graphs,
  statistics, diagrams, treemap, theme and source relationships come from
  existing DocuMint renderer code.
- With the **same discovered source files and project metadata**, content
  generation follows the same code path. Date/nonces are intentionally random;
  exact byte-for-byte HTML equality is not a goal.
- Local-only execution; no HTTP API, no MCP and no login.
- File scan skips symlinks, generated folders, tests, dependencies, hidden
  directories and secret-like paths by default; explicit file targets allowed
  within the selected root, no silent partial document on exceeded budgets.
- Offline HTML CSP and generated asset hardening is preserved.
- For ChatGPT environments with no command execution, a Skill alone cannot run
  Node. It must disclose the limitation and may offer a Markdown-only fallback,
  never falsely claim HTML parity or that CLI ran.

## Non-goals / limitations
- **AI provider mode** is not reproduced. The target is the VS Code **Local**
  (no-AI) interactive HTML output.
- VS Code workspace API filtering / workspace settings / .gitignore are not
  universally available outside VS Code. The CLI uses shared default language
  and exclusions; inventories can differ until matched by explicit targets.
- Public ChatGPT directory listing is separately subject to plugin approval.
- No package publish/merge to main as part of implementation.

## Tests
- Disk scanning language map, default excludes, symlink protections, boundaries
  and fail-closed budgets.
- Local HTML/Markdown uses the same rendering stack, including interactive
  code map, offline assets and cache.
- CLI argument validation and observable output paths.
- Plugin package includes compiled Node CLI as an executable asset; packaging
  fails explicitly if the bundle cannot be created.
- VS Code test suite and typecheck on integrated checkout.
